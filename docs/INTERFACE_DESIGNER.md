# AI-Verse Interface Designer

AI-Verse Interface Designer is the member-facing capability for designing, rebuilding, improving and reviewing interfaces.

You describe what you want. AI-Verse decides which design specialists are actually needed for that job.

You do not need to choose a framework, vendor, design Skill or deployment platform before asking for help.

## What it can design

Use Interface Designer for work such as:

- websites and landing pages;
- persistent GitHub-hosted HTML/CSS/JavaScript artifacts;
- dashboards and operational interfaces;
- React web apps when the project already uses React or you explicitly choose it;
- PWAs;
- desktop-app interfaces;
- native/mobile interface design;
- React Native and Expo interfaces;
- Figma interface work;
- Canva/static-design targets when appropriate;
- redesigns of existing products;
- reference recreation from screenshots, video or an existing interface;
- interaction-heavy components such as draggable panels, sheets and direct-manipulation controls;
- immersive scroll-driven experiences;
- final visual, responsive, motion and accessibility review.

## It does not lock you into a stack

Interface Designer starts by detecting the real delivery target.

A plain HTML/CSS/JavaScript project stays plain HTML/CSS/JavaScript unless you ask to migrate it.

An existing non-React website is not converted to React just because React expertise is available.

A project does not need Vercel hosting.

A project does not need shadcn.

A project does not need Figma.

The design intelligence is portable. Stack-specific specialists are loaded only when the actual project requires them.

## How to use it

Ask for the outcome in normal language.

Examples:

> Build me a dashboard for monitoring my AI agents.

> Recreate this screenshot inside my current website.

> Redesign this page but keep the current tech stack.

> Make this floating panel draggable and make the motion feel physical and native.

> Build three genuinely different versions of this component so I can choose one.

> Audit the animations in this finished interface.

> Create an immersive cinematic scroll landing page.

> Make this Expo bottom sheet feel native on iPhone and Android.

> Review the final UI on desktop and mobile and fix visual problems.

## What happens automatically

Depending on the request, Interface Designer can:

1. inspect the current project and its existing design authority;
2. classify the size of the task;
3. detect the implementation target;
4. analyze supplied references;
5. establish UI/UX and visual direction when needed;
6. preserve or update the project's persistent `DESIGN.md`;
7. choose only the relevant implementation and interaction specialists;
8. implement or hand off to the correct target;
9. render and inspect meaningful states;
10. review motion, mobile behavior and web/accessibility quality;
11. fix failures and re-check affected states.

A tiny spacing change does not invoke the full process.

## Persistent design memory

For substantial products, Interface Designer can use a project-local `DESIGN.md`.

This records stable decisions such as:

- product design principles;
- typography;
- color roles;
- spacing and layout;
- surfaces and elevation;
- component rules;
- interaction language;
- motion language;
- responsive and mobile direction;
- accessibility constraints;
- product-specific patterns to avoid.

Existing `DESIGN.md` decisions are read before substantial design changes.

A small one-off edit does not rewrite the design system.

## Reference recreation

You can provide:

- a screenshot;
- a screen recording;
- a reference website;
- a reference app/interface;
- a visual direction.

Interface Designer can separate exact-reference work from inspired-by-reference work.

For exact recreation, reference fidelity takes priority over arbitrary originality.

For inspired work, AI-Verse can preserve the useful design principles without blindly reproducing the same structure.

## Originality without random design

For a genuinely new direction, Interface Designer checks whether the proposed interface is only a familiar template with different colors.

It can compare structural dimensions such as:

- information architecture;
- navigation;
- layout grammar;
- density;
- typography hierarchy;
- materials/surfaces;
- interaction model;
- motion language;
- primary composition;
- signature elements.

This check stays inside the current authorized project/workspace. One member's private design history is not used to constrain another member's work.

## Motion and interaction

Motion specialists are conditional.

They can help with:

- direct manipulation;
- drag and swipe behavior;
- sheets and panels;
- springs and interruption;
- transitions;
- motion construction;
- animation review;
- Expo/Reanimated interaction;
- scroll-driven experiences.

A normal dashboard is not forced to contain decorative animation or a "signature interaction."

## Visual QA

For substantial interfaces, visual completion requires rendered evidence when the runtime supports it.

Applicable states can include:

- loading;
- empty;
- populated;
- error;
- hover/focus/active;
- disabled;
- expanded/collapsed;
- dialogs and sheets;
- desktop;
- tablet;
- mobile;
- light/dark;
- reduced motion.

If a state cannot actually be rendered or inspected, AI-Verse must report it as unverified rather than pretending it passed.

## Mobile is designed, not merely shrunk

For substantial responsive products, mobile gets its own art-direction check.

That includes:

- mobile information hierarchy;
- navigation;
- touch behavior;
- layout/order changes;
- table and dense-data treatment;
- image/media crop and layering;
- safe areas;
- keyboard/overlay behavior;
- mobile motion and reduced motion.

A desktop layout that technically fits on a phone is not automatically considered finished.

## Scroll experiences

When scrolling is the experience itself, Interface Designer can activate its dedicated scroll specialist and verify multiple semantic scroll states.

Ordinary pages that simply scroll normally do not load that specialist.

## Security and authority

Interface Designer is a Skill orchestrator, not a permission system.

Installing or selecting a design Skill does not grant:

- file permissions;
- credentials;
- network access;
- external-tool approval;
- workspace authority.

AI-Verse Skills keeps package integrity, admission, trust, readiness and execution authorization separate.

## In short

You can treat Interface Designer as one capability:

**"Design, build or improve this interface properly."**

AI-Verse handles the internal specialist routing while preserving the project's real stack, existing design system and security boundaries.
