# Interface Designer Handoff for AI-Verse Video Editor

Use this handoff only when visual expertise materially improves the requested video.

The Video Editor remains the editor. Interface Designer is a presentation specialist.

## Four allowed handoff modes

### 1. Visual direction

Use for a substantial graphic language, typography, palette, composition system, or
video-specific visual identity.

Return presentation rules to Video Editor. Do not alter transcript, EDL, source
mapping, cut order, or timing anchors.

### 2. Reference recreation

Use when a screenshot, website, reel, frame sequence, or named visual reference should
shape the look.

Video Editor owns editorial pacing/timing analysis. Interface Designer owns visual
reconstruction analysis only.

Never claim reference-audio facts unless the audio was actually inspected by an
audio-capable Video Editor review path.

### 3. Prototype visual directions

Use for meaningful ambiguous visual decisions or when the user explicitly asks for
options. Prototype one bounded representative beat/section before rebuilding the
whole edit.

Do not prototype every routine lower third or turn prototype exploration into a
mandatory ceremony.

### 4. Motion taste

Use for specialist advice on pacing, easing, continuity, emphasis, gesture and motion
language.

HyperFrames owns implementation/runtime correctness. Editorial anchors own timing.
Motion-taste advice cannot stretch, shift, or reinterpret those anchors without a
Video Editor decision.

## Handoff packet

When calling Interface Designer, pass only the information it needs:

- the locked editorial meaning;
- brand/design constraints;
- relevant visual references;
- target format and safe areas;
- representative source/render frames when useful;
- beat duration and transcript anchor when motion is being reviewed;
- exact-reference versus inspiration boundary.

Do not hand it authority it does not need.

## Return packet

Interface Designer returns presentation decisions, alternatives, risks and unknowns.
Video Editor converts the accepted presentation direction into the canonical
HyperFrames project and owns the subsequent lint/check/preview/render/media-QA loop.

## Hard boundary

Interface Designer never owns:

- transcript truth;
- silence, mistake or retake cuts;
- EDLs;
- source-time mapping;
- hook/open-loop/payoff editorial structure;
- caption timing truth;
- audio/video synchronization;
- HyperFrames runtime correctness;
- final encoded-media acceptance.

If visual-motion guidance conflicts with the canonical HyperFrames provider, the
provider wins for implementation. If visual preference conflicts with locked
editorial truth, editorial truth wins.
